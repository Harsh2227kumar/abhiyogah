# Abhiyogah console

Next.js (App Router, TypeScript strict, pnpm) console for Internal Ombudsman offices, compliance
officers and auditors.

```sh
pnpm install
pnpm dev        # http://localhost:3000
pnpm check      # eslint + tsc --noEmit + vitest (also run by `make check` via `console-check`)
```

All data shown is synthetic.

## API client and mock

The console talks to the engine only through `lib/api` (`getApi()`); types come from
`lib/api/generated/schema.ts`, generated by openapi-typescript. Never write API types by hand.

Until the platform stream publishes `openapi.json`, everything provisional lives in `mock/`:

- `mock/provisional_api.py` declares the endpoints the console reads, with the Pydantic domain and
  registry models from `src/abhiyogah/` as response types, and writes `provisional.openapi.json`.
- `mock/build_fixtures.py` runs the real evaluator over synthetic complaints at a fixed set of
  `as_of` instants and writes `fixtures.json` (with one deliberately broken hash chain).
- `mock/obligations/` holds DRAFT copies of rule-pack files, used only while `rules/obligations/` is
  empty on `main`.

`pnpm mock` regenerates all three outputs. Set `ABHIYOGAH_API_URL` to use a live engine instead.

Switching to the real API: run `OPENAPI_SPEC=../openapi.json pnpm openapi`, point the
"generated client" test at `../openapi.json`, set `ABHIYOGAH_API_URL`, then delete `mock/`.
